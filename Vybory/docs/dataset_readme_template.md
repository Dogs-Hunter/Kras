# Датасет протоколов № 2 УИК — Государственная Дума, 2026

## Состав

`all_uiks.csv` содержит 89 132 строки данных. Одна строка соответствует одной уникальной участковой избирательной комиссии (УИК) и её текущему строго проверенному протоколу № 2 по федеральному избирательному округу. Уникальный ключ — сочетание `election_id` и официального UUID `uik_id`; локальный номер `uik_number` сам по себе не уникален.

Обнаружено 91 399 УИК. Получено 89 132 валидных протокола, поэтому покрытие равно `89 132 / 91 399 = 97,5196665%`. Для 2 267 УИК индивидуальный протокол недоступен через проверенный официальный интерфейс.

## Числовые показатели

Колонки `line_01`–`line_22` обязательны, целочисленны и неотрицательны:

1. избиратели в списке на момент окончания голосования;
2. бюллетени, полученные УИК;
3. бюллетени, выданные досрочно;
4. бюллетени, выданные в помещении;
5. бюллетени, выданные вне помещения;
6. погашенные бюллетени;
7. бюллетени в переносных ящиках;
8. бюллетени в стационарных ящиках;
9. недействительные бюллетени;
10. действительные бюллетени;
11. утраченные бюллетени;
12. бюллетени, не учтённые при получении;
13–22. голоса за десять федеральных списков в официальном порядке.

Полные официальные формулировки находятся в `protocol_schema.json`, а соответствие строк 13–22 политическим партиям — в `political_parties.json`. Отсутствующее обязательное значение не заменяется нулём; протокол с таким значением не попадает в строгий CSV.

## Метаданные и даты

- `election_date` — дата выборов.
- `protocol_date` — `signDateTime`, подтверждённая дата и время подписания протокола. Пустое значение означает, что источник его не предоставил.
- `source_created_at` — исходное поле `createdAt`. Официальное клиентское приложение называет его «Датой генерации»; это не подтверждённая дата публичного опубликования. Значение сохранено как исходная строка ISO-8601 со смещением `+03:00`, без подмены и пересчёта.
- `retrieved_at` — UTC-время получения ответа программой.
- `source_record_id` — идентификатор официальной записи отчёта.
- `source_url` — URL использованного официального endpoint.
- `protocol_version=repeated` означает официальный признак повторного протокола, а не наличие предыдущей версии в локальной базе.
- `precinct_address` пуст, поскольку надёжный массовый способ получения адреса из проверенного интерфейса не подтверждён.

## Недоступные индивидуальные протоколы

`missing_protocols.csv` содержит 2 267 записей: ДНР — 764, ЛНР — 651, Запорожская область — 659, Херсонская область — 193. Диагностический статус `Unknown` означает только то, что индивидуальный endpoint вернул HTTP 404 при проверенном запросе; это не доказывает, что протокол никогда не публиковался.

Для 101 соответствующей ТИК доступны официальные агрегаты. Агрегат ТИК не позволяет однозначно восстановить результаты каждой УИК, поэтому значения не распределялись, не вычислялись и не заменялись нулями.

## Файлы и целостность

- `federal_districts/` — представления по округам, субъектам и ТИК;
- `special_precincts/` — специальные, зарубежные и байконурские участки;
- `deg/` — участки ДЭГ, если они классифицированы отдельно;
- `commissions.json` — справочник комиссий;
- `invalid_protocols.csv` и `discrepancies.csv` — диагностические выгрузки;
- `report.json` — статистика с явно указанным знаменателем покрытия;
- `manifest.json` — относительный путь, размер и SHA-256 каждого файла релиза.

Для проверки SHA-256 в PowerShell:

```powershell
Get-FileHash -Algorithm SHA256 .\all_uiks.csv
```

Полученный хэш должен совпасть с записью `all_uiks.csv` в `manifest.json`. Сам `manifest.json` не включает собственный хэш.

## Ограничение происхождения

Для новых загрузок сохраняется буквальное тело HTTP-ответа до десериализации. Для исторически загруженных 89 132 протоколов сохранена повторная сериализация Rust-модели. Их 22 значения полностью сверены между JSON, SQLite и CSV, а 54 протокола повторно совпали с официальным API, но побайтовая идентичность историческим HTTP-ответам не заявляется.
