# Технический обзор Vybory

## Назначение

Vybory — консольный Rust-проект для воспроизводимого получения, проверки, хранения и экспорта протоколов № 2 УИК на выборах депутатов Государственной Думы IX созыва 20 сентября 2026 года. Протокол № 2 относится к федеральному избирательному округу и содержит 12 общих показателей и результаты десяти федеральных списков.

## Поток данных

```text
официальный JSON API
        ↓
ограниченный HTTP-клиент + кэш
        ↓
строгая модель и проверка идентичности УИК
        ↓
22 строки + арифметические соотношения
        ↓
транзакционная SQLite и история версий
        ↓
CSV/JSON, отчёт и SHA-256-манифест
```

Иерархия ЦИК → ИКСРФ → ОИК → ТИК → УИК загружается рекурсивно. Дедупликация использует ID кампании и официальный UUID комиссии. Очередь `download_jobs` позволяет возобновлять сбор после прерывания. Невалидные ответы не включаются в строгий экспорт.

## Компоненты

- `src/api.rs` — официальный API, challenge, ограничение частоты и повторы;
- `src/pipeline.rs` — обнаружение комиссий, очередь, загрузка и сверка ТИК;
- `src/validation.rs` — разбор строк и контрольные соотношения;
- `src/db.rs` — транзакции и происхождение источников;
- `src/export.rs` — детерминированный экспорт и манифест;
- `src/main.rs` — CLI и ограничение путей корнем проекта.

WebDriver не используется: официальное приложение само обращается к структурированному JSON API, а HTML содержит обфусцированное представление части цифр.

## Даты

`election_date`, `protocol_date`, `source_created_at` и `retrieved_at` имеют разные значения. `createdAt` в клиенте подписан как «Дата генерации», поэтому он хранится как `source_created_at`, а не как доказанная дата публикации. Исходное смещение `+03:00` сохраняется. В SQLite историческая колонка `protocol_versions.published_at` оставлена для совместимости; точное финальное имя находится в `protocol_source_metadata.source_created_at`.

## Проверка достоверности

Каждый строгий протокол содержит ровно 22 неотрицательных целых значения. Проверяются три арифметических соотношения. Полные наборы УИК сверяются с отдельно полученными и сохранёнными официальными агрегатами ТИК. Источник агрегата, тело, report ID и SHA-256 сохраняются в SQLite.

## Воспроизводимость

Команда `elections export` автономно строит полный релизный комплект из SQLite, включая описание датасета. Служебные времена генерации могут отличаться, поэтому воспроизводимость числовых данных проверяется по ключу УИК и строкам 1–22, а не побайтовым сравнением всего релиза.
