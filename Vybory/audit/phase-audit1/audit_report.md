# Phase Audit 1 — аналитический отчёт

Дата аудита: 2026-10-11. Область проверки: только `C:\Game\Kras\Vybory`.

## Резюме

Критических искажений официальных числовых результатов (P0) не обнаружено. Сплошная проверка всех 89 132 принятых протоколов показала точное совпадение 22 числовых строк между сохранённым JSON, SQLite и исходным `all_uiks.csv`; конфликтов, пропавших исходных документов и дубликатов УИК нет. Повторное обращение к официальному сервису для 54 разнообразных УИК также дало 54/54 совпадения всех 22 строк и идентификатора отчёта.

При этом подтверждены недостатки доказуемости происхождения, сохранения источников агрегатной проверки и отчётности. Они перечислены ниже. Этот документ создан до исправления Rust-кода и служит границей между этапами A и B.

## Подтверждённые факты

### Происхождение 89 132 протоколов

- Проверено 89 132 из 89 132 принятых протоколов.
- Для каждого проверены: SHA-256 тела в `source_documents`, байтовое совпадение с файлом кэша, идентификатор УИК, `protocolNum=2`, идентификатор официального отчёта, уникальность строк и числовое совпадение строк 1–22 с CSV.
- Совпали 89 132; отсутствующих локальных исходных документов — 0; конфликтов — 0; неоднозначных локально сохранённых версий — 0.
- Настоящие нули сохраняются как целые значения. Округления нет. Все 10 партий соответствуют строкам 13–22.
- Выборочно повторно запрошены 54 УИК из 50 обычных субъектов, зарубежной территории, Байконура и крайних по размеру участков: HTTP 200 — 54, совпадение 22 строк — 54, совпадение report ID — 54.

Ограничение: историческое тело HTTP-ответа не было сохранено буквально. `OfficialApi::protocol` сначала десериализовал ответ в `ApiReport`, затем создавал «raw» через `serde_json::to_string`. Поэтому локальная сплошная проверка доказывает согласованность преобразованных данных, а внешняя выборка — актуальное совпадение с официальным сервисом; она не доказывает побайтовую идентичность всех исторических HTTP-ответов.

### Независимость агрегатов ТИК

Код агрегатной сверки отдельно запрашивает официальный отчёт ТИК через `/reports/242?...&protocolNum=2` и сравнивает его 22 строки с суммами текущих строгих протоколов УИК. Следовательно, 2 839 выполненных сверок были независимыми на момент запуска, а не сравнением двух локально вычисленных сумм.

Контроль на временной копии базы изменил строку 13 одной УИК на +1. Повторная сверка родительской ТИК обнаружила ровно одно расхождение. Основная база не менялась.

Недостаток: в `aggregate_checks` сохранены только числа и время, но не URL, report ID, тело и хэш отдельно опубликованного агрегата. Поэтому результат 2 839 проверок нельзя полностью воспроизвести офлайн. Все 101 пропущенные ТИК имеют отдельно опубликованный официальный агрегат из 22 строк, однако локальный набор УИК у каждой неполон; корректно сравнивать агрегат как равенство сумме нельзя. Распределение неполных ТИК: ДНР 36, ЛНР 31, Запорожская область 20, Херсонская область 14.

### 2 267 ответов HTTP 404

Все записи локально относятся к существующим комиссиям типа 5, имеют UUID, кампанию 587813923, report ID 242 и `protocolNum=2`. Они сосредоточены в четырёх субъектах: ДНР 764, ЛНР 651, Запорожская область 659, Херсонская область 193.

Повторно проверены по четыре УИК каждого субъекта (16 всего): официальный endpoint снова вернул HTTP 404. Родительские официальные агрегаты для всех 101 затронутой ТИК доступны. Ни локальные данные, ни небольшая внешняя выборка не доказывают, что индивидуальные протоколы не опубликованы вообще; документированный альтернативный официальный источник индивидуальных протоколов не подтверждён. Поэтому статус всех 2 267 записей — `Unknown`, основание — корректный запрос к индивидуальному endpoint возвращает 404. Восстановлено 0 протоколов; нули не подставлялись.

### Версии

У 176 текущих отчётов установлен официальный признак `repeated=true`. Ни у одной УИК не сохранено более одной физической версии. Противоречия нет: `repeated` описывает официальный признак текущей публикации, а `multiple_versions` — число протоколов с несколькими локальными записями версий. Для всех 176 предыдущая публикация в локальном наборе отсутствует; создавать её искусственно нельзя.

### География

Все 333 записи без федерального округа классифицируются по официальной иерархии: 326 относятся к ТИК «Территория за пределами РФ», 7 — к ТИК «Город Байконур (Республика Казахстан)». Назначать им российский федеральный округ нельзя. Нужны отдельные категории `foreign` и `baikonur`, не влияющие на уникальный общий итог.

### Адреса и даты

В сохранённом основном ответе отчёта адресов нет; 91 399 записей precinct имеют пустой адрес. В коде официального приложения обнаружен отдельный `/commissionOrg/{id}` для сведений о комиссии. Проверка трёх УИК с UUID дала HTTP 404, а с известным числовым `internal_id` — HTTP 400 (`address_sample.json`). Надёжное сопоставление параметра и извлечение адреса не подтверждены; массовые запросы не выполнялись.

У всех 89 132 отчётов `signDateTime` отсутствует, а `createdAt` присутствует и уже хранится как `published_at`. Подменять дату подписания датой голосования или публикации нельзя. Недостаток экспорта: отдельное поле `published_at` в CSV отсутствует.

### Нормативная основа

Подтверждено постановление ЦИК России от 19.08.2026 № 41/288-9 «О формах протоколов и сводных таблиц об итогах голосования, о результатах выборов, составляемых избирательными комиссиями при проведении выборов депутатов Государственной Думы Федерального Собрания Российской Федерации девятого созыва». Приложения 3 и 4 относятся к протоколу УИК № 2, приложения 8 и 10 — к протоколу и сводной таблице ТИК № 2. Доступная копия текста указывает на официальное опубликование в сетевом издании «Вестник Центральной избирательной комиссии Российской Федерации»; прямой устойчивый URL официального экземпляра в ходе проверки не найден, поэтому вторичную ссылку следует обозначать именно как копию.

## Проверка Rust и SQLite

- `PRAGMA integrity_check`: `ok`; `foreign_key_check`: 0 нарушений; режим журнала WAL.
- Транзакция сохранения протокола атомарно пишет источник, версию, значения, валидацию, текущую версию и состояние задания.
- Ограничение частоты и повторные попытки присутствуют; challenge принимает только ожидаемое арифметическое выражение.
- Значения разбираются в `i64`, строки 1–22 дедуплицируются и валидируются; SQL использует параметры.
- Экспорт сортируется детерминированно, компоненты путей очищаются.
- Подтверждённый пробел надёжности — отсутствие обязательной проверки идентичности запрошенной и возвращённой УИК перед записью.

## Решение по этапу B

Разрешены адресные исправления перечисленных подтверждённых недостатков. Полная повторная общероссийская загрузка не требуется. Числовые значения официальных протоколов изменять нельзя; кандидатный экспорт должен сохранить 89 132 уникальные УИК и все их 22 значения.
