# Vybory

Консольное приложение на Rust для воспроизводимого сбора, хранения, проверки
и экспорта официальных протоколов № 2 УИК на выборах депутатов Государственной
Думы Федерального Собрания Российской Федерации девятого созыва
20 сентября 2026 года.

Проект обрабатывает только голосование по федеральному избирательному округу,
то есть по федеральным спискам политических партий. Протоколы № 1
одномандатных округов не смешиваются с датасетом.

## Состояние

Рабочий pipeline получает необфусцированный JSON официального сервиса
izbirkom.ru, рекурсивно обнаруживает комиссии, сохраняет прогресс в SQLite,
проверяет все строки 1–22 и экспортирует одну строку CSV на один УИК.

На 10 октября 2026 года выполнен полный общероссийский обход: обнаружено
91 399 уникальных УИК, получено 89 132 полных протокола (97,5196665%). Для
2 267 УИК четырёх субъектов индивидуальная конечная точка официального API
возвращает 404; это не считается доказательством отсутствия публикации.
Записи имеют диагностический статус `Unknown` и перечислены в
`missing_protocols.csv` со статусом `failed` и не подменяются нулями.
Проверены 2 839 полных ТИК, расхождений по строкам 1–22 не найдено; 101
неполная ТИК корректно пропущена. Дубликатов, неполных или арифметически
некорректных сохранённых протоколов нет. Точные показатели находятся в
`output/2026/report.json`. Поэтому выгрузка является максимально полной по
доступному официальному источнику, но не объявляется абсолютно полной.

Подробности исследования: [docs/research.md](docs/research.md).

## Протокол № 2

Обязательные общие показатели:

1. Число избирателей, внесённых в списки на момент окончания голосования.
2. Число бюллетеней, полученных УИК.
3. Число бюллетеней, выданных проголосовавшим досрочно.
4. Число бюллетеней, выданных в помещении в день голосования.
5. Число бюллетеней, выданных вне помещения в день голосования.
6. Число погашенных бюллетеней.
7. Число бюллетеней в переносных ящиках.
8. Число бюллетеней в стационарных ящиках.
9. Число недействительных бюллетеней.
10. Число действительных бюллетеней.
11. Число утраченных бюллетеней.
12. Число бюллетеней, не учтённых при получении.

Строки 13–22 содержат результаты десяти партий. Точные исходные формулировки
и соответствие партий сохраняются в protocol_schema.json и
political_parties.json. Программа никогда не заменяет пропуск нулём:
состояния missing, parse_error, unpublished и untrusted отличаются от
настоящего числового нуля.

## Архитектура и технологии

Основной pipeline целиком написан на Rust stable. `tokio` и `reqwest`
обеспечивают ограниченную асинхронную загрузку, `rusqlite` — транзакционное
хранилище, `serde` — строгие модели JSON, `csv` — экспорт, `clap` — CLI,
`tracing` — диагностику. Python и WebDriver в рабочем pipeline не
используются.

    Vybory/
    ├── src/          # API-клиент, модели, SQLite, проверки, экспорт и CLI
    ├── migrations/   # идемпотентные миграции SQLite
    ├── tests/        # автономные integration-тесты и фикстуры
    ├── docs/         # результаты исследования источника
    ├── data/         # место для входных справочников
    ├── cache/        # буквальные официальные HTTP-ответы для новых загрузок; исторические ответы до Phase Audit 1 были повторно сериализованы
    ├── database/     # устойчивая база и прогресс
    └── output/2026/  # воспроизводимая выгрузка

Комиссии хранятся отдельными сущностями, а все встреченные связи — в
`commission_relations`. УИК идентифицируется официальным UUID вместе с
кампанией, а не локальным номером. Контекст ИКСРФ, ОИК и ТИК сохраняется
отдельными полями; повторное появление комиссии в дереве не создаёт второй
УИК.

## Сборка

Требуется Rust stable.

    cd C:\Game\Kras\Vybory
    cargo build --release

Зависимости зафиксированы в Cargo.lock. SQLite собирается встроенно через
rusqlite/bundled; отдельная установка SQLite не нужна.

## Команды

    # Исследовать всю кампанию и сформировать очередь УИК
    cargo run --release -- discover --rate-limit 10

    # Ограниченный пилот
    cargo run --release -- run --region 01 --limit 20 --concurrency 4 --rate-limit 8

    # Продолжить, включая ранее неуспешные задания
    cargo run --release -- resume --concurrency 8 --rate-limit 10

    # Автономно перепроверить сохранённые протоколы
    cargo run --release -- validate

    # Сверить только полностью загруженные ТИК
    cargo run --release -- verify --region 01 --rate-limit 8

    # Экспортировать SQLite без повторного обращения к сети
    cargo run --release -- export

    # Показать фактическую статистику
    cargo run --release -- stats

Поддерживаются фильтры --federal-district, --region, --tik, --uik,
--limit, а также --concurrency, --rate-limit, --offline, --headless,
--output и --force в применимых командах. --headless сохранён для
совместимости CLI, но браузер не запускается. Все пути принудительно
ограничиваются корнем проекта.

Повторный запуск идемпотентен: завершённые задания не скачиваются снова,
официальный report ID уникален, а прерванные задания возвращаются в очередь.
Ctrl+C прекращает выдачу новых заданий после завершения уже начатых запросов.

Для массового сбора сначала выполните `discover`, затем `run`. После любой
остановки запускайте `resume`; неуспешные задания сохраняют причину и число
попыток. После загрузки используйте `validate`, `verify`, `export` и `stats`.
Покрытие выводится в целом, по субъектам и по федеральным округам. Сводка
отдельного сетевого запуска также содержит число HTTP-запросов, повторов,
сетевых ошибок и продолжительность.

## Проверки

Для каждого протокола проверяются:

- тип протокола № 2;
- единственность каждой строки и наличие строк 1–22;
- неотрицательные целые значения;
- 2 = 3 + 4 + 5 + 6 + 11 − 12;
- 7 + 8 = 9 + 10;
- 10 = сумма строк 13–22;
- источник, официальный UUID УИК и текущая версия.

Неполные и ошибочные записи остаются в SQLite, но не попадают в строгий
all_uiks.csv. Неполная сумма УИК не сравнивается с полной сводной таблицей
ТИК.

## SQLite

База: database/elections.sqlite.

Основные таблицы:

- elections;
- commissions, commission_relations, precincts;
- source_documents;
- protocols, protocol_versions, protocol_values, protocol_source_metadata;
- political_parties;
- download_jobs, download_errors;
- validation_results, aggregate_checks, aggregate_sources;
- protocol_availability_checks.

Включены внешние ключи, WAL, транзакции, уникальные ограничения и сохранение
версий. Ответы дополнительно кэшируются в cache/raw/protocols. Начиная с Phase Audit 1 тело успешного HTTP-ответа сохраняется до десериализации; для ранее загруженных 89 132 записей сохранена повторная сериализация модели, поэтому их побайтовая историческая идентичность не утверждается.

## Экспорт

    output/2026/
    ├── all_uiks.csv
    ├── federal_districts/<округ>/<субъект>/<ТИК_UUID>.csv
    ├── special_precincts/all.csv
    ├── deg/
    ├── protocol_schema.json
    ├── political_parties.json
    ├── commissions.json
    ├── missing_protocols.csv
    ├── invalid_protocols.csv
    ├── discrepancies.csv
    ├── report.json
    ├── README_DATASET.md
    └── manifest.json

CSV записывается в UTF-8 со стабильным порядком колонок и строк. Одна строка
соответствует одной уникальной УИК. Метаданные дат разделены:
`election_date` — дата выборов, `protocol_date` — `signDateTime`,
`source_created_at` — исходное `createdAt`, которое официальный клиент
показывает как «Дату генерации», `retrieved_at` — UTC-время получения.
`createdAt` не называется подтверждённой датой публикации и сохраняется
без пересчёта как ISO-8601 со смещением источника. В
manifest.json находятся SHA-256, размеры файлов, версия программы и
количество строгих записей. ДЭГ не преобразуется в искусственные УИК.

## Ограничения

- Основной ответ протокола не содержит адрес. Обнаруженный в коде официального
  приложения `/commissionOrg/{id}` проверен на малой выборке, но известные UUID
  дали 404, а числовые внутренние идентификаторы — 400. Надёжное сопоставление
  не установлено, поэтому массовые запросы не выполняются, а
  `precinct_address` остаётся пустым и не подменяется.
- Повторный общероссийский проход занимает около 70–75 минут при лимите
  25 запросов/с. `resume` повторяет только задания со статусом `failed`.
- На дату проверки отчёты 2 267 УИК ДНР, ЛНР, Запорожской и Херсонской
  областей недоступны через индивидуальную конечную точку report=242 (официальный сервис отвечает HTTP 404). Причина остаётся `Unknown`; нулевые или фиктивные протоколы не создаются.

- `protocol_date` — только официальная дата подписания (`signDateTime`) и потому остаётся пустой, когда она не опубликована. `source_created_at` — дата генерации записи из поля `createdAt`; это не доказанная дата публикации.
- 326 зарубежных участков и 7 участков Байконура имеют отдельные категории `foreign` и `baikonur`; российский федеральный округ им не назначается.
- `official_repeated_protocols` считает официальный флаг повторного протокола, `uiks_with_multiple_saved_versions` — фактически сохранённые несколько версий, `repeated_without_prior_saved_version` — повторные публикации без доступной предыдущей версии.
- Агрегатная сверка сохраняет отдельно опубликованный ответ ТИК, URL, report ID и SHA-256 в SQLite, поэтому её источник доступен для офлайн-аудита.
- Публичный сервис в исследуемой среде доступен по HTTP; исходные JSON и
  контрольные суммы сохраняются для аудита.
- Если официальный источник меняет challenge или схему, клиент завершает
  работу с ошибкой вместо исполнения произвольного JavaScript или
  предположительного парсинга.

## Статистика категорий

В `report.json` каждая категория содержит отдельные показатели
`discovered_uiks`, `received_protocols`, `missing_protocols` и
`coverage_percent`. Знаменатель покрытия всегда `discovered_uiks`.

| Категория | Обнаружено | Валидных протоколов | Недоступно |
|---|---:|---:|---:|
| regular | 88 348 | 86 081 | 2 267 |
| special | 2 718 | 2 718 | 0 |
| foreign | 326 | 326 | 0 |
| baikonur | 7 | 7 | 0 |

Показатели версий имеют разную семантику:

- `official_repeated_protocols = 176` — текущие протоколы с официальным флагом `repeated`;
- `uiks_with_multiple_saved_versions = 0` — УИК с несколькими физически сохранёнными версиями;
- `repeated_without_prior_saved_version = 176` — повторные протоколы, предыдущая версия которых локально недоступна.

Наличие `repeated` не доказывает наличие предыдущей версии в базе.

Подробное описание структуры данных находится в
`output/2026/README_DATASET.md`, а обзор архитектуры — в
`docs/technical_overview.md`.
