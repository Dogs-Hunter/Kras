## Крупные файлы и Git LFS

В планируемой поставке найдено 6 файлов больше 10 МиБ, 5 файлов больше
50 МиБ и 0 файлов больше 100 МиБ:

| Файл | Размер, МиБ |
|---|---:|
| `Aeroporty/output/release/airports.json` | 84,45 |
| `Vybory/output/2026/all_uiks.csv` | 75,45 |
| `Aeroporty/output/release/airports.csv` | 72,43 |
| `Aeroporty/output/release/airports.yaml` | 59,89 |
| `Aeroporty/output/release/airports.toml` | 58,98 |
| `Vybory/output/2026/commissions.json` | 42,70 |

Git LFS 3.7.1 установлен, но не включён. Ни один планируемый файл не превышает
лимит обычного GitHub-файла 100 МиБ, а отказ от LFS делает учебный clone
самодостаточным и не зависит от квоты LFS. Создан `.gitattributes`, который
фиксирует LF для исходников и документации, а финальные датасеты Aeroporty,
Inflyaciya и Vybory помечает `-text`: Git не меняет их байты и не нарушает
SHA-256-манифесты при checkout на Windows. SQLite помечены как binary.
Перед публикацией на ином хостинге следует проверить его лимиты; обязательные
результаты нельзя просто исключать.

Локально остаются файлы свыше 100 МиБ, но они исключены: четыре SQLite Vybory
размером примерно 1,35–1,38 ГиБ каждая и сборочные продукты до очистки. Для
передачи рабочей базы Vybory отдельно подходят Git LFS или релизный архив,
однако для просмотра финального датасета база не нужна.
