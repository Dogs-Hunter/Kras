# Aeroporty

`Aeroporty` — учебный проект на Rust для воспроизводимого сбора, строгой проверки и экспорта мирового набора аэропортов с ICAO. Финальный релиз 1.0.0 содержит **10 573 аэропорта и 14 259 физических наземных ВПП**. Базовый мировой каталог OurAirports дополняется и проверяется официальными FAA/NASR и ANAC; сомнительные или неполные записи в строгий экспорт не попадают.

Это не перечень абсолютно всех аэропортов планеты. В набор включаются только объекты с ICAO, хотя бы одной полностью описанной наземной ВПП и всеми обязательными атрибутами. Набор не предназначен для навигации или задач безопасности полётов.

## Быстрый старт

Нужен Rust stable 1.88 или новее. Готовый проверенный набор находится в `output/release/`.

```powershell
cargo build --release
cargo test
cargo run --release -- validate --output output/release
```

Полное воспроизведение из сохранённых локальных снимков и повторная атомарная публикация:

```powershell
cargo run --release -- run --offline
cargo run --release -- release
```

Команда `release` не копирует Phase 5 вслепую: она заново проверяет обязательные значения, ICAO/ID, ВПП, evidence, восемь разрешённых конфликтов и эквивалентность четырёх форматов, после чего публикует каталог через временную директорию.

## Схема данных

| Объект | Обязательные поля | Тип и единица |
|---|---|---|
| Аэропорт | `icao`, `latitude`, `longitude`, `status`, `type`, `country`, `elevation_ft`, `timezone`, `runways_count`, `id`, `name` | координаты — `float` WGS84; высота — целые футы MSL; timezone — IANA; status — `open`/`close` |
| ВПП | `id`, `length_ft`, `surface` | длина — положительный `float` в футах; покрытие — непустая известная строка |

JSON, TOML и YAML хранят массив аэропортов с вложенными ВПП. CSV содержит одну строку на физическую ВПП, повторяет поля аэропорта и сохраняет provenance/evidence в JSON-колонках, поэтому исходная вложенная модель восстанавливается без потерь. `id`, ICAO и название являются разными полями и не подменяют друг друга.

### Реальный пример: KSEA

```json
{
  "icao": "KSEA",
  "name": "Seattle–Tacoma International Airport",
  "status": "open",
  "type": "large_airport",
  "country": "United States",
  "elevation_ft": 433,
  "timezone": "America/Los_Angeles",
  "runways_count": 3,
  "runways": [
    {"id":"254330","length_ft":9426.0,"surface":"PEM","le_ident":"16C","he_ident":"34C"},
    {"id":"242182","length_ft":11901.0,"surface":"PEM","le_ident":"16L","he_ident":"34R"},
    {"id":"242181","length_ft":8500.0,"surface":"PEM","le_ident":"16R","he_ident":"34L"}
  ]
}
```

Пример взят непосредственно из релиза; он показывает, что три физические полосы не сворачиваются в одну и для каждой сохраняются собственные длина и покрытие.

## Возможности

- HTTPS-загрузка `airports.csv`, `runways.csv` и `countries.csv` OurAirports, условные запросы, retries и offline-кэш;
- проверка схемы кэшированных CSV до обработки;
- join по `id`/`airport_ref`, использование именно `icao_code`;
- классификация строк как `land_runway`, `waterway`, `helipad`, `unknown` или `invalid`;
- карантин повреждённых, неполных, дублирующихся и неоднозначных строк;
- геодезические проверки координат концов, расстояния до аэропорта и геометрической длины;
- IANA timezone через `tzf-rs` с сохранением версии, всех кандидатов и причины неоднозначности;
- типизированные свидетельства по каждому обязательному полю;
- версионированная загрузка FAA/NASR, безопасное извлечение ZIP, SHA-256 manifest и offline-проверка;
- сопоставление FAA по официальному `ICAO_ID`, региону, координатам и ключу `SITE_NO + SITE_TYPE_CODE`;
- независимая проверка и восстановление из `APT_BASE`, `APT_RWY`, `APT_RWY_END`;
- неизменяемые снимки ANAC public/private V2, SIROS и диагностических таблиц с SHA-256;
- сопоставление ANAC по ICAO, CIAD, стране и координатам, включая безопасное распознавание переобозначенных ВПП;
- добавление только полностью заполненных частных аэродромов ANAC через общий validation pipeline;
- конфликты источников без молчаливого перезаписывания;
- машинный реестр подтверждений конфликтов и diff реальных снимков без трактовки отсутствия записи как закрытия;
- строгая валидация и эквивалентный экспорт CSV, JSON, TOML и YAML;
- отдельные отчёты по исключениям, карантину, географии и evidence.

## Phase 5: достоверность и история

`data/phase5_conflict_evidence.csv` — декларативный реестр решений, а не набор специальных веток в коде. Общее правило требует текущую официальную запись и отдельную официальную публикацию либо подписанный акт с перечнем характеристик. Оно разрешает семь расхождений FAA по длине ВПП и SIRI по LCA к Portaria 18.582/SIA. Старое конфликтное evidence остаётся в записи как `NotComparable`, выбранное документированное значение добавляется как `Recovered`.

`data/phase5_baseline.json` фиксирует SHA-256 всех 21 артефактов Phase 4. Перед сборкой Phase 5 каждый файл проверяется, поэтому прежний выпуск нельзя незаметно изменить. Аналогично manifest кэша официальных PDF/XML и независимого JSON ANAC проверяется по размеру и SHA-256 при каждом запуске.

Текущие public V2 CSV и JSON содержат 496 записей, но физические поля ВПП отсутствуют в CSV и равны `null` во всех JSON-объектах. Поэтому 230 отсутствующих в union публичных объектов оценены индивидуально, но не добавлены из выгрузки 2023/2024. Аналогично 25 частных кандидатов остаются вне strict export: 17 без измеренной высоты, 4 без высоты и актуального регистрационного акта, 4 без акта.

`version_changes.csv` сравнивает фактический снимок ANAC general 2023 с V2 от 2026-10-01 по CIAD. Числа, метрические единицы, DMS/decimal координаты, регистр и пробелы нормализуются до сравнения. Отсутствие записи в новой схеме обозначает только наблюдение `absent`, а не закрытие; пустые runway-поля public V2 не считаются удалением ВПП. Исторические значения никогда не продвигаются в текущий датасет автоматически.

Машинная сверка Phase 4 находится в `phase4_reconciliation.csv`: `8448 + 2109 + 9 - 1 = 10565`. Phase 5 возвращает восемь документированно разрешённых конфликтных объектов. Все 2109 новых ANAC-only ICAO отдельно проверяются на устойчивый CIAD-derived ID, уникальность, статус, наличие физической ВПП и прохождение общей валидации.

Обычный `run` использует закреплённый OurAirports snapshot и не перезаписывает базовый кэш предыдущих фаз; сеть применяется к выбранному версионированному выпуску FAA. Обновление OurAirports выполняется только явной командой `update`, после чего изменение snapshot должно рассматриваться как отдельная ревизия данных.

## ANAC Phase 4

Подключены официальные `Lista de aeródromos públicos V2` и `Lista de aeródromos privados V2`. Снимок находится в `cache/anac/<release>/`; manifest хранит URL, дату получения, размер, SHA-256, результат проверки реальной схемы и решение об интеграции. Public V2 используется для независимой проверки существующих аэропортов. Private V2 дополнительно содержит до двух физических ВПП и может создавать новые полные кандидаты.

`CIAD` и ICAO не смешиваются: ICAO связывает мировой объект, CIAD связывает таблицы и формирует устойчивый ID в отдельном namespace `0xD...`. Совпадение требует единственного официального ICAO и согласованных координат в пределах 15 км; имя не является самостоятельным ключом. Точное обозначение полосы канонизируется, а изменение магнитного номера допускается только на ±1 одновременно для обоих концов и при согласованной физической длине. Одинаковая длина сама по себе полосы не объединяет.

ANAC сообщает высоту и длины в метрах. Используется точный коэффициент `3.280839895013123`; raw метрическое значение остаётся в evidence/provenance. `Comprimento` трактуется как физическая длина. TORA, TODA, ASDA, LDA и размеры защитной полосы не подставляются вместо неё. Португальские покрытия нормализуются документированной таблицей (`Asfalto → ASPHALT`, `Concreto → CONCRETE`, `Grama → GRASS`, `Terra → DIRT`, `Cascalho → GRAVEL`, `Piçarra/Saibro → LATERITE`), составные значения сохраняют все компоненты.

Для нового частного аэродрома обязательны уникальные ICAO/CIAD, координаты, название, измеренная высота, регистрационный акт и хотя бы одна полная физическая наземная ВПП. Тип сохраняется как общий `airport`, поскольку реестр сообщает правовой тип использования, а не размерную категорию. `status=open` выводится только из присутствия в актуальном private V2 и регистрационного акта; это не NOTAM и не гарантия фактической доступности. Такие значения имеют `Recovered`/`Derived`, но не `IndependentlyVerified`.

Официальные `Características Gerais` (выгрузка сервера 2023) и `Pistas de Pouso e Decolagem` (2024) загружаются и проверяются. Фактический CSV полос без заголовка имеет недокументированную 15-колоночную смешанную схему, поэтому устаревшие строки не восстанавливают обязательные значения. Текущий SIROS `aerodromos.csv` содержит ICAO, название и координаты, но не elevation/ВПП; он сохранён как диагностический снимок, а не объявлен независимым вторым регулятором.

Правовая основа самих открытых баз зафиксирована отдельно от футера веб-страниц. Decreto № 8.777/2016 определяет федеральные открытые данные как опубликованные под открытой лицензией, разрешающей свободное использование и объединение с указанием источника, и требует неограниченного повторного использования баз. Страницы ANAC одновременно показывают CC BY-ND 3.0 для содержимого сайта. Оба факта сохранены в manifest и `sources_and_licenses.csv`; каждый использованный атрибут содержит атрибуцию ANAC и CIAD.

Метрики `faa/anac.independently_verified_values` относятся к решениям адаптера до общей validation. `statistics.attributes.independently_verified` и поля `phase3/phase4` считают уникальные обязательные позиции только в итоговом строгом наборе. Поэтому FAA `16 815` против Phase 3 `16 720` — не ошибка сложения: 95 source-level решений относятся к кандидатам, не вошедшим в strict export. Аналогично девять ANAC-подтверждений остаются за пределами Phase 4 strict export из-за последующей проверки/конфликта.

## FAA/NASR Phase 2

Зафиксированный выпуск по умолчанию вступил в силу **2026-10-01**. Архив берётся с официального HTTPS-адреса FAA. В `cache/faa/<release>/manifest.json` сохраняются URL, effective date, HTTP ETag/Last-Modified, размер и SHA-256 архива, а также имена, размеры, SHA-256 и результат проверки схемы таблиц. Путь каждого ZIP entry проверяется; извлекаются только три объявленные таблицы. Выпуски не смешиваются.

FAA Location Identifier (`ARPT_ID`), внутренний `SITE_NO`, `ICAO_ID` и ID OurAirports считаются разными идентификаторами. Префикс `K` не достраивается. Аэропорт сопоставляется только при единственном точном официальном ICAO, допустимом региональном охвате и расстоянии reference points не более 15 км; имя является дополнительным evidence, но не ключом. ВПП связываются по канонической паре направлений с поддержкой обратного порядка. Одинаковая длина сама по себе не объединяет ВПП.

Длины FAA читаются в футах, elevation — в футах MSL с документированной точностью до 0,1 ft. Исходные FAA surface codes сохраняются; составные покрытия не сокращаются до одного материала. `ARPT_STATUS` используется как прямое свидетельство постоянного статуса, а `FACILITY_USE_CODE` — нет. `O` означает operational в NASR, `CI`/`CP` — indefinite/permanent closure; это не NOTAM и не гарантия доступности конкретного рейса.

Решения принимаются по полю: `IndependentlyVerified` означает согласование двух источников; `Recovered` — значение есть только в FAA; `Conflicting` — серьёзное противоречие, блокирующее строгий экспорт; `NotComparable` — различающиеся определения, классификации или даты без автоматического выбора победителя. Для координат, elevation и длины применяются разные допуски. FAA не перезаписывает непустое значение только из-за официальности или более новой даты.

## Расширение каталога в Phase 3

FAA records с валидным ICAO, отсутствующим в OurAirports, теперь являются самостоятельными кандидатами. В строгий набор попадает только уникальный FAA type `A` с известными координатами, названием, elevation, документированным `ARPT_STATUS`, поддерживаемой страной и хотя бы одной полностью заполненной наземной ВПП. Heliport, seaplane base, неизвестные покрытия, неполные строки, неоднозначные ICAO и объекты вне региональной политики остаются в `faa_candidate_assessment.csv`.

Все FAA-only значения имеют метод `Recovered`, а не `IndependentlyVerified`. Timezone вычисляется тем же общим модулем IANA и проходит ту же строгую валидацию. ID не зависит от порядка строк: это 64-битный SHA-256-derived идентификатор в отдельном namespace `0xE...`, вычисленный из `FAA/NASR + SITE_NO + SITE_TYPE_CODE`. Коллизия с существующим ID блокирует кандидата.

`recovery_candidates.csv` содержит детерминированную очередь оставшихся исключений: сначала записи, которым не хватает одного измеримого атрибута, затем отсутствие ВПП, timezone и конфликты. Оценка объяснима и не использует ML.

Международные источники проверяются до загрузки с учётом доступа и лицензии. AISWEB требует ключ; структурированные EAD downloads требуют регистрации/соглашения; OpenAIP имеет ограничение CC BY-NC; SKYbrary не является массовым официальным аэродромным реестром. Поэтому они перечислены в `sources_and_licenses.csv`, но их данные не включаются без ключа, соглашения или совместимого разрешения.

## Что считается физической ВПП

Одна строка OurAirports не считается обычной ВПП автоматически: по словарю источника она может описывать land runway, waterway или helipad. Классификатор использует тип аэродрома, покрытие, обозначения концов, длину, ширину и целостность строки.

- В строгий датасет входят только полностью валидные `land_runway`.
- `waterway` и `helipad` не входят в число обычных физических ВПП.
- `unknown` не превращается в land runway ради полноты.
- Короткая полоса не считается helipad только из-за длины.
- Одна строка с направлениями `09/27` считается одной физической полосой.
- Неполная возможная land runway карантинируется и блокирует аэропорт: `runways_count` искусственно не уменьшается.
- Явно повреждённая строка без длины, покрытия и распознаваемого обозначения карантинируется отдельно и не уничтожает другие доказанные ВПП.

Карантин означает «строка не признана достоверной и сохранена для диагностики», а не «объект физически не существует».

## Семантика Status

Пользовательская схема сохраняет `open`/`close`, но это **статус существования и постоянного закрытия по классификации источника на дату его данных**:

- `closed`/`closed_airport` производно преобразуется в `close`;
- известный поддерживаемый тип, не помеченный закрытым, производно преобразуется в `open` по документированной политике;
- неизвестный тип не получает выдуманное значение и не проходит строгий экспорт.

`open` не означает доступность для конкретного рейса прямо сейчас, отсутствие временного NOTAM-закрытия или наличие регулярных пассажирских рейсов. Статус отдельной ВПП хранится независимо.

## Происхождение и доказательства

Каждое обязательное значение может иметь несколько свидетельств. Evidence содержит источник, ID исходной записи, дату получения и effective/publication date, если известна, raw/normalized value, способ получения, результат проверки и сведения о конфликте.

- `SourceReported` — значение непосредственно сообщено источником.
- `Derived` — значение вычислено воспроизводимым правилом.
- `IndependentlyVerified` — согласовано с действительно независимым источником.
- `Unresolved` — сведений недостаточно.
- `Conflicting` — источники противоречат друг другу.

Парсинг, проверка диапазона, round-trip экспорта и согласование разных CSV одной базы не являются независимым подтверждением. Только согласованное значение из независимого официального источника получает `IndependentlyVerified`.

## Географическая проверка

Модуль `geo` использует haversine-расстояние на поверхности Земли. Он проверяет диапазоны координат, расстояние airport reference point — конец ВПП и согласованность геометрической/заявленной длины. Отсутствие необязательных координат концов само по себе не исключает запись. Умеренные расхождения дают warning; заведомо невозможные комбинации дают error и блокируют строгий экспорт до разрешения конфликта.

## Конфликты и enrichment

`data/enrichment.json` необязателен; структура показана в `data/enrichment.example.json`. Значение заполняется только при отсутствии. Несовпадение сохраняет оба свидетельства и создаёт конфликт; обязательный неразрешённый конфликт блокирует экспорт. Пустые обозначения ВПП не совпадают друг с другом, неоднозначное сопоставление является ошибкой, дубли ICAO в enrichment запрещены.

В `sources::EvidenceSource` подготовлен общий контракт будущих адаптеров FAA/NASR, eAIP и других стран: сопоставление ICAO/альтернативных ID и конкретных ВПП, даты актуальности, независимые наблюдения и конфликты. Массовая загрузка FAA, SKYbrary или OpenAIP в Phase 1 не реализуется.

`report.json` отдельно считает заполненные, структурно валидные, сообщённые источником, вычисленные, независимо подтверждённые, конфликтующие и неразрешённые обязательные значения. ## Воспроизводимость и исходные снимки

`run --offline` воспроизводит закреплённый выпуск без сети и проверяет manifests/SHA-256 источников. Команда `update` означает получение более новых данных и поэтому может закономерно изменить результат. Подробный перечень локальных снимков, которые необходимо хранить отдельно от обычного Git-репозитория, приведён в `REPRODUCIBILITY.md`.

В Git включаются исходный код, тесты, небольшие декларативные фикстуры, документация, аудит и `output/release/`. `target/`, `tmp/`, рабочий `cache/` и промежуточные `output/candidate-phase*` исключены. Кэш не удалён: он остаётся локальной воспроизводимой копией источников, но из-за размера и сторонних бинарных документов не предназначен для обычного Git.

## Проверки разработчика

```powershell
cargo fmt --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test
cargo build --release
cargo run --release -- run --offline
cargo run --release -- validate
cargo run --release -- release
cargo run --release -- validate --output output/release
```

OurAirports остаётся глобальным базовым источником; FAA/NASR независимо покрывает только свою региональную область. Неизвестные данные за её пределами, неоднозначные timezone и серьёзные конфликты остаются причинами исключения. Результат предназначен для учебных, исследовательских и аналитических задач, **не для оперативной аэронавигации**.
