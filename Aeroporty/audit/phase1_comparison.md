# Aeroporty — сравнение исходной версии и Phase 1

Дата: 2026-10-09  
Исходный набор: `output/`  
Новый кандидат: `output/candidate-phase1/`  
Режим обработки: offline, на тех же сохранённых CSV OurAirports.

## 1. Резюме

Phase 1 изменила не источник данных, а правила интерпретации, доказательства и строгого допуска. Старый `output/` и исходные CSV не перезаписывались. Контрольный SHA-256 старого `output/airports.json` и `cache/dataset.json` остался одинаковым: `7FC1467CDD883A4CE95128C6973CB1A23524AA2EDEC2018A448BA0C1E5A74347`.

Основной результат:

- устранены все 37 подтверждённых аудитом ложных ВПП: 29 waterways и 8 helipads в 30 ранее принятых аэропортах;
- KSEA и ещё 7 аэропортов больше не отклоняются из-за явно повреждённой отдельной строки;
- VAAM и WAJI исключены из строгого набора из-за очевидных географических противоречий;
- KMRF остаётся отклонённым: реальная полоса с неизвестным покрытием не была искусственно удалена или заполнена вручную;
- число независимо подтверждённых обязательных значений честно равно 0, поскольку Phase 1 не подключает официальный массовый источник;
- старое арифметическое число «117 125 подтверждённых атрибутов» заменено раздельными фактическими метриками.

## 4. Новая классификация строк ВПП

В `runways.csv` всего 48 330 строк. Классификация требует типа связанного аэропорта, поэтому отчёт честно разделяет область:

|---|---:|
| Land-runway candidates в ICAO-области | 11 684 |
| Waterways в ICAO-области | 40 |
| Helipads в ICAO-области | 99 |
| Unknown type | 13 |
| Invalid/duplicate | 13; duplicate может пересекаться с land candidate |
| Строки вне области аэропортов с ICAO | 36 482 |
| Land runways в строгом финальном датасете | 10 908 |

Классификатор не использует длину как единственный критерий. Положительная длина и явно невода-поверхность позволяют сохранить короткую или не имеющую ширины land runway; helipad определяется по типу аэродрома и характерным обозначениям. `Unknown` блокирует аэропорт, если строка может быть обязательной ВПП.

## 6. Status

Внутреннее состояние допускает отсутствие окончательного status. Для известных типов политика следующая:

- `closed`/`closed_airport` → `close`, метод `Derived`;
- известный не-closed тип → `open`, метод `Derived`;
- неизвестный тип → unresolved/отклонение.

`open` теперь документирован как «объект не помечен источником как постоянно закрытый на дату его классификации». Он не означает текущую минутную доступность, NOTAM-status или регулярные рейсы. В текущих 10 531 ICAO-записях неизвестного типа не оказалось, поэтому число status-unresolved равно 0. При этом независимо подтверждённых status также 0.

## 7. Timezone

Алгоритм по-прежнему не выбирает произвольный пояс при overlap. Теперь для каждой записи сохраняются:

- версия polygon dataset `tzf-rs`;
- все кандидаты;
- `unique_polygon_match`, `ambiguous_polygon_match`, `no_polygon_match` или `insufficient_coordinates`;
- evidence `Derived` или `Unresolved`.

Результат по строгому набору не изменён: 30 аэропортов отклонены из-за неоднозначности — 29 с кандидатами `Asia/Shanghai`/`Asia/Urumqi` и UGSS с `Asia/Tbilisi`/`Europe/Moscow`. Исправление требует документированной политики или независимого источника, поэтому Phase 1 не подставляет default.

## 8. Evidence и статистика обязательных полей

Старая метрика `validated_required_attributes=117125` была формулой и больше не используется. Метрики Phase 1 вычислены проходом по фактическим обязательным значениям строгого датасета:

| Метрика | Значение |
|---|---:|
| Filled | 117 116 |
| Structurally valid | 117 116 |
| SourceReported | 86 428 |
| Derived | 30 688 |
| IndependentlyVerified | 0 |
| Conflicting в строгом датасете | 0 |
| Unresolved в строгом датасете | 0 |

Сумма методов равна числу обязательных значений. `SourceReported` не называется подтверждённым. Derived включает country join, status policy, timezone polygon resolution и `runways_count`. Конфликтующие и unresolved обязательные значения не допускаются в строгий экспорт.

VCCC остаётся в текущем candidate, потому что Phase 1 намеренно не импортирует внешнюю AIP-публикацию и не может проверить effective-date. Добавлен regression test: при наличии конфликтующего официального свидетельства оба значения сохраняются, конфликт не перезаписывается, а VCCC-подобная запись блокируется. Фактическое разрешение VCCC относится к Phase 2.

## 9. Архитектурные изменения

- `Evidence`, `EvidenceMethod` и `EvidenceMap` поддерживают несколько свидетельств, raw/normalized value, source record ID, retrieval/effective dates, validation и conflict.
- `RunwayKind` разделяет land/water/helipad/unknown/invalid.
- `QuarantineRecord` хранит источник, строку/record ID, причину, raw context и влияние на аэропорт.
- `GeographicIssue` разделяет warning/error/insufficient.
- `TimezoneResolution` хранит candidates/version/outcome.
- `sources::EvidenceSource` и `SourceObservation` — общий, не FAA-специфичный контракт для будущих NASR/eAIP адаптеров.
- enrichment отклоняет дубли ICAO и неоднозначное runway matching; пустые designation больше не совпадают.
- повреждённая CSV-строка карантинируется вместо остановки всего парсинга; кэш проверяется по ожидаемым headers и наличию data rows.
- результаты Phase 1 публикуются отдельно; обработанный старый cache dataset не перезаписывается.

## 11. Тесты и проверки

Итоговое покрытие: 19 тестов — 3 модульных и 16 интеграционных. Добавлены проверки:

- waterway, несколько вариантов helipad и короткая land runway;
- одна строка `09/27` = одна ВПП;
- повреждённая строка не уничтожает валидные ВПП аэропорта;
- неполная возможная ВПП остаётся в quarantine и блокирует экспорт;
- KSEA-style regression;
- SourceReported не становится IndependentlyVerified;
- status без evidence отклоняется;
- конфликт не перезаписывается, VCCC-style конфликт блокирует экспорт;
- VAAM regression;
- ambiguous timezone без default;
- фактические report metrics;
- round-trip четырёх форматов с evidence;
- schema-invalid cache отклоняется.

Пройдены:

```text

cargo clippy --all-targets --all-features -- -D warnings
cargo test                         # 19 passed
cargo build --release
cargo run --release -- run --offline

```

## 12. Ограничения до Phase 2

1. FAA/NASR, EUROCONTROL и national eAIP ещё не импортируются; `IndependentlyVerified=0` является правильным результатом.
2. KMRF не восстановлен без официального значения surface.
3. VCCC-конфликт воспроизведён тестом, но не применён к production data без versioned external observation.
4. 514 ICAO с влияющим карантином требуют внешней проверки или более сильного правила сопоставления.
5. 30 timezone требуют policy/independent evidence.
6. 96 географических warnings требуют triage; warning сам по себе не исключает аэропорт.
7. Country пока подтверждается join внутри OurAirports, а не независимой географией.
8. Status описывает постоянную классификацию источника, а не оперативные NOTAM.
9. Evidence дублируется в четырёх пользовательских форматах и sidecar; компактный профиль экспорта можно сделать отдельно.

## 13. Итоговая оценка

Увеличение accepted с 7 666 до 7 672 не является самоцелью: оно состоит из восьми обоснованных восстановлений после изоляции повреждённых строк и двух новых строгих географических исключений. Одновременно устранены все 37 подтверждённых ложных посадочных объектов. Phase 1 не заявляет независимую проверку там, где её не было, не подставляет значения KMRF/VCCC/timezone вручную и создаёт проверяемую основу для Phase 2.
